## Every token can look at every token

For a sequence of length n, queries and keys produce an n by n score matrix. This gives the transformer flexible access to context, but it also means that doubling n creates four times as many pairwise scores before values are combined. The quadratic term is a memory and compute constraint, not merely a benchmark footnote.

## Useful context has a price

A longer window can connect a definition near the beginning of a document to a question near the end. But the model must store or recompute more keys and values, and the attention kernel must move more data. Long-context methods therefore change the attention pattern, the position representation, the memory layout, or all three.

## Use a fixed question

When you move the context control, keep the hidden size fixed and ask what changed: the number of token representations, the pairwise score matrix, or both. The right mental model is that context length changes the geometry of the computation even when the model weights do not change.

$$
\text{attention scores} \in \mathbb{R}^{n \times n} \quad \Rightarrow \quad \text{work} \propto n^2
$$

## Recap

The central idea is **Context length**. The implementation detail matters because it changes what the model can learn, how much memory or compute the system needs, or how confidently we can interpret its behavior. Keep the equation visible, name the controlled variables, and treat every benchmark or safeguard as part of the model’s operating definition.
