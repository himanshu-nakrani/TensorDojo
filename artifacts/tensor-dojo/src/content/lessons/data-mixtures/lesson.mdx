## A corpus is a probability distribution

Suppose the corpus contains web pages, code, books, and conversations. The model does not automatically learn each domain in proportion to its raw disk size. A sampler can assign mixture weights, so a small but valuable domain appears more often than its byte count would suggest. The resulting training distribution is a weighted mixture of domain distributions.

## More data is not the same as better data

A large noisy domain can overwhelm a smaller high-quality domain. Upweighting code may improve programming evaluations while changing general prose behavior; upweighting books may improve long-form structure while reducing exposure to short factual patterns. Mixture design is therefore a measurable tradeoff, not a cosmetic preprocessing choice.

## Read the histogram as a policy

Use the workbench to compare raw proportions with the sampled proportions. Ask which domain would be under-trained if the sampler followed storage size exactly, and which domain would be overrepresented after reweighting. The important habit is to separate corpus composition from sampling policy.

$$
p(x) = \sum_{d \in \text{domains}} \pi_d \, p_d(x)
$$

## Recap

The central idea is **Data mixtures**. The implementation detail matters because it changes what the model can learn, how much memory or compute the system needs, or how confidently we can interpret its behavior. Keep the equation visible, name the controlled variables, and treat every benchmark or safeguard as part of the model’s operating definition.
