## Replicate the weights, split the examples

In data parallel training, every worker holds the same parameters. Each worker reads a different mini-batch and computes a local gradient. An all-reduce operation averages or sums those gradients so every replica applies the same update and stays synchronized.

## The batch grows with the world

With R workers and a local batch of B examples, the global batch is approximately R times B. That can improve hardware utilization, but it also changes the optimization noise scale. Learning-rate schedules, warmup, and gradient accumulation must be interpreted in terms of the global batch rather than the local one alone.

## Communication is part of the algorithm

The gradient average is mathematically simple and operationally expensive. The workers cannot finish an update independently if they must agree on the next weights. Move between training presets and ask whether the bottleneck is arithmetic, input throughput, or synchronization.

$$
g = \frac{1}{R} \sum_{r=1}^{R} g_r
$$

## Recap

The central idea is **Distributed data parallel**. The implementation detail matters because it changes what the model can learn, how much memory or compute the system needs, or how confidently we can interpret its behavior. Keep the equation visible, name the controlled variables, and treat every benchmark or safeguard as part of the model’s operating definition.
