## A cache is a growing tensor

During decoding, each new token adds a key and value vector for every layer and head. If requests have different lengths, a dense allocation sized for the maximum wastes space. If the server repeatedly moves cache rows to make them contiguous, memory copies become a hidden bottleneck.

## Use a block table

Paged attention divides the cache into fixed-size blocks and keeps a logical-to-physical block table for each sequence. The attention kernel follows the table when reading keys and values. Sequences can grow by claiming another block, and completed sequences release their blocks for reuse.

## Fragmentation becomes visible

The block size trades internal slack against metadata and kernel complexity. Small blocks reduce unused tail space but increase bookkeeping; large blocks make indexing simpler but can waste more memory for short requests. The workbench makes that tradeoff concrete.

$$
\text{blocks} = \left\lceil \frac{\text{tokens}}{\text{block size}} \right\rceil
$$

## Recap

The central idea is **Paged attention**. The implementation detail matters because it changes what the model can learn, how much memory or compute the system needs, or how confidently we can interpret its behavior. Keep the equation visible, name the controlled variables, and treat every benchmark or safeguard as part of the model’s operating definition.
