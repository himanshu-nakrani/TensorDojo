## The model sees a sequence

System messages, user requests, retrieved pages, emails, and tool results may all become tokens in one context. The model can learn patterns that make imperative text look authoritative even when it came from an untrusted document. The boundary humans see in the application may be weak inside the sequence.

## Defense in depth

Prompt delimiters and explicit labels help, but robust systems also constrain tools, validate arguments, minimize privileges, filter outputs, and require confirmation for consequential actions. No single string such as “ignore previous instructions” is the whole threat model; the risk comes from granting a model authority over actions while mixing trusted and untrusted text.

## Test the boundary adversarially

Use the toggles to compare a plain prompt with isolation and tool-validation layers. Ask which layer catches an injection and which layer merely makes it less likely. Security claims should be tied to an explicit threat model and an observable control.

## Recap

The central idea is **Prompt injection**. The implementation detail matters because it changes what the model can learn, how much memory or compute the system needs, or how confidently we can interpret its behavior. Keep the equation visible, name the controlled variables, and treat every benchmark or safeguard as part of the model’s operating definition.
