## Preferences are comparative data

A labeler may find response A better than response B without assigning either one an absolute numeric score. A reward model learns a scalar function r(x, y) whose ordering should match those comparisons. The score is not truth; it is a learned proxy for the preference data supplied to training.

## The margin carries the signal

The pairwise loss rewards a positive gap between the preferred and rejected responses. If the model already ranks them correctly, the loss is small; if the ranking is reversed, the loss is large. This creates a smooth objective from discrete preference pairs.

## Proxy objectives can be gamed

Once a policy is optimized against the reward model, it may find high-scoring patterns that humans would not endorse. That is reward hacking: the proxy is optimized more successfully than the underlying goal. A good lesson keeps the proxy and the target visibly separate.

$$
\mathcal{L} = -\log \sigma\bigl(r(x,y^+) - r(x,y^-)\bigr)
$$

## Recap

The central idea is **Reward models**. The implementation detail matters because it changes what the model can learn, how much memory or compute the system needs, or how confidently we can interpret its behavior. Keep the equation visible, name the controlled variables, and treat every benchmark or safeguard as part of the model’s operating definition.
