## One linear layer, many devices

A projection y = xW can be split by columns of W. Each device computes a slice of the output, and concatenating those slices reconstructs the full vector. A row split uses a different communication pattern: devices produce partial sums that must be reduced. The math is unchanged; the placement of the terms changes.

## Partitioning creates communication edges

Tensor parallelism saves per-device memory and increases aggregate throughput, but every split introduces a boundary where activations or partial results must move. A useful design keeps communication on fast links and chooses partitions that balance both storage and arithmetic.

## Shape discipline prevents silent bugs

Use the shape lab to write the dimensions before thinking about hardware. If X is B by d and W is d by h, the output is B by h. A column partition gives each device B by h/p, while a row partition requires a reduction over matching partial outputs.

$$
Y = XW = [XW_1 \; XW_2 \; \cdots \; XW_p]
$$

## Recap

The central idea is **Tensor parallelism**. The implementation detail matters because it changes what the model can learn, how much memory or compute the system needs, or how confidently we can interpret its behavior. Keep the equation visible, name the controlled variables, and treat every benchmark or safeguard as part of the model’s operating definition.
